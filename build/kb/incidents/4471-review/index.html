Parser: shared month-first interpretation

The shared parser reads month first for day-first tenants. App and email reports, and forms without the booking-v3 month-first hint, follow this path. For example, R-41200 from Harbour Dental reports 7 April becoming 4 July; R-41205 belongs here even though intake tagged it hint. Parser issue.

Use the tenant’s date order or a validated unambiguous date format at the parsing boundary. Test ambiguous dates and day values above twelve, without depending on the reporter’s browser locale.

Hint: booking-v3 advertises the wrong order

For day-first tenants, booking-v3 prints MM/DD/YYYY, but the form reads input in the tenant’s date order. People following the hint therefore get a different date. This path requires the form channel and booking-v3; a booking-v3 tenant’s app report is not automatically a hint problem. R-41230 from Copper Studio belongs here despite its intake parser tag. Hint issue.

Make the displayed hint match the form’s actual locale-aware reader. Test both day-first and month-first tenants and input entered exactly as the hint instructs. Fixing the shared parser alone does not fix this misleading instruction.
